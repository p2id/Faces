===PATTERNS_MD===
Date: 2026-11-22
Project ID: project-001

Dominant patterns:
- Clear hierarchy, compact headers, grouped content, persistent navigation, and visible state.
- List, table, card, split-pane, and detail-drawer structures with consistent alignment.
- Neutral surfaces, restrained accent color, semantic status colors, and high-contrast text.
- Search, filter, sort, selection, inline edit, and reversible actions.

Emerging patterns:
- Compact, comfortable, and expanded density modes.
- Contextual action bars that reduce repeated navigation.
- Progressive disclosure for advanced options.
- Responsive reflow from multi-column views to prioritized stacks.
- User-configurable columns, filters, and view preferences.

Deprecated patterns:
- Low-contrast decorative gradients.
- Deep navigation without location context.
- Unlabeled icon-only controls.
- Auto-advancing panels, persistent popups, and irreversible primary actions.

Outlier patterns:
- Split views preserving overview while exposing detail.
- Instructional empty states without decorative illustration.
- Inline validation with reserved space to prevent layout shift.
- Dense data views with explicit overflow and density controls.

Extracted DNA:
Visual: neutral canvas, limited elevation, 8px spacing rhythm, 1px borders, medium-radius geometry, one primary accent, semantic color reserved for state.
Interactional: predictable focus order, explicit selection, visible hover and pressed states, keyboard-complete actions, reversible destructive operations, immediate non-blocking feedback.
Accessibility: strong contrast, visible focus, semantic headings and landmarks, text labels for controls, minimum 44px targets, reduced-motion support, no color-only meaning.
Responsive: fluid containers, mobile-first priority, readable minimum widths, stacked content below tablet width, controlled overflow for dense data, persistent primary action where practical.

Candidate domains:
- Planning calendar: organizes dates, schedules, and related details in a time-based workspace.
- Knowledge library: structures searchable reference items with metadata, filters, and detail views.
- Metrics dashboard: presents values, trends, comparisons, and status summaries.
- Asset catalog: manages browsable records with previews, attributes, and batch controls.
- Preference console: groups configurable options with explicit state and validation.
- Workflow board: presents ordered items across states with filtering and movement.

===EVIDENCE_MD===
Supporting evidence summary:
- Reusable interface conventions favor clear hierarchy, compact spacing, semantic status, and predictable navigation.
- Time-based structures support transferable patterns for grouping, filtering, detail inspection, and priority.
- Neutral palettes with one restrained accent improve scanability and reduce visual competition.
- Progressive disclosure supports compact screens without removing advanced capability.
- Keyboard access, visible focus, semantic labeling, reduced motion, and non-color status encoding are baseline requirements.
- Reversible actions, stable layouts, and explicit confirmation reduce interaction errors.
- Planning calendar has the highest weighted fit across clarity, task fit, responsive behavior, accessibility, and extensibility.
- Evidence confidence: moderate; general principles are reusable, while domain assumptions require validation.

===DIRECTION_A===
Positioning: Calm operational workspace optimized for rapid scanning and low cognitive load.
Palette rationale: Warm off-white canvas, graphite text, slate surfaces, and muted blue accent create focus without visual severity; amber and red are state-only.
Type rationale: Neutral sans serif with strong numeral clarity, moderate x-height, and two primary weights.
Layout rules: Persistent wide-screen navigation, 12-column grid, compact summary row, structured primary list, right-side detail panel, stacked layout below 760px.
Motion intent: 120–180ms fades and panel transitions; preserve spatial continuity; honor reduced-motion settings.
Avoided traps: Excessive cards, decorative gradients, hidden filters, unlabeled icons, ambiguous date formats, and adjacent destructive and primary actions.

===DIRECTION_B===
Positioning: Structured planning surface balancing overview, time context, and focused detail.
Palette rationale: Cool neutral canvas, light surfaces, deep navy text, and restrained teal accent support precision; semantic colors are limited to status and validation.
Type rationale: Legible sans serif with tabular numerals for dates and values, clear heading scale, and generous line height.
Layout rules: Utility bar, compact navigation rail, primary time or sequence view, persistent filter row, optional detail drawer, 8px spacing rhythm, 44px minimum controls, prioritized stacking below 900px.
Motion intent: Subtle selection emphasis, drawer transitions up to 180ms, no auto-play or parallax, and quiet immediate feedback.
Avoided traps: Grid overload, hidden overflow, hover-only information, color-only status, validation layout shift, and excessive modal use.

===DIRECTION_C===
Positioning: Flexible information surface for configurable views and progressive detail.
Palette rationale: Light gray canvas, white surfaces, charcoal text, and violet-blue accent support customization while maintaining neutrality; semantic colors remain sparse.
Type rationale: Compact sans serif with distinct labels, values, and supporting text; tabular numerals for comparison.
Layout rules: Resizable content frame, configurable density, optional secondary column, grouped controls above content, adjacent or below-detail view, single-column fallback below 640px.
Motion intent: Soft expand and collapse transitions, clear reorder feedback, no continuous motion, and reduced-motion alternatives.
Avoided traps: Unbounded customization, inconsistent alignment, overloaded settings, excessive disclosure levels, tiny targets, and controls without persistent state.

===DIRECTION_SELECTION===
Selected direction: Direction B — Structured planning surface.
Rationale: Best fit for the locked Planning calendar domain while remaining transferable to library, dashboard, catalog, preference, and board experiences. It combines hierarchy, responsive prioritization, accessibility, and restrained visual identity.
Lock scope: Direction B, selected domain, extracted DNA, palette logic, type logic, layout rules, motion limits, and avoided traps.
Fallback: Use Direction A for lower-density operational experiences; use Direction C when configurable views are the primary requirement.
